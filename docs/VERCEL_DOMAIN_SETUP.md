# Vercel Deployment & Custom Domain Setup

## Overview

This guide walks through deploying **JGA Enterprise OS** to Vercel with the custom domain **jgaos2026-gif.com**. Vercel's free Hobby tier supports full Next.js including all serverless API routes (`/api/*`), middleware, and edge functions.

---

## 1. Create a Vercel Account

1. Go to [vercel.com](https://vercel.com) and click **Sign Up**.
2. Choose **Continue with GitHub** — this links your GitHub account so Vercel can access your repositories.

---

## 2. Import the Repository

1. In the Vercel dashboard, click **Add New → Project**.
2. Under "Import Git Repository", find **jgaos2026-gif/Sovereign-Stitch-JGA** and click **Import**.
3. Vercel auto-detects Next.js and reads `vercel.json` automatically.
4. Do **not** change the Framework Preset — leave it as **Next.js**.
5. Do **not** set `Output Directory` — Vercel manages `.next` automatically.

---

## 3. Configure Environment Variables

Before clicking **Deploy**, expand the **Environment Variables** section and add the following. All are required for full functionality:

| Variable | Where to get it |
|---|---|
| `NEXT_PUBLIC_SUPABASE_URL` | Supabase project → Settings → API → Project URL |
| `NEXT_PUBLIC_SUPABASE_ANON_KEY` | Supabase project → Settings → API → anon/public key |
| `SUPABASE_SERVICE_ROLE_KEY` | Supabase project → Settings → API → service_role key (**secret — server-only**) |
| `STRIPE_SECRET_KEY` | Stripe Dashboard → Developers → API keys |
| `STRIPE_WEBHOOK_SECRET` | Stripe Dashboard → Webhooks → Signing secret |
| `NEXT_PUBLIC_APP_URL` | Set to `https://jgaos2026-gif.com` |
| `JWT_SECRET` | Generate: `openssl rand -hex 32` |

> **Important:** `SUPABASE_SERVICE_ROLE_KEY` and `STRIPE_SECRET_KEY` must **never** be exposed in the browser. They are only used in server-side API routes.

Click **Deploy**. Vercel will build and publish the app to a `*.vercel.app` subdomain in ~2 minutes.

---

## 4. Connect the Custom Domain `jgaos2026-gif.com`

### 4a. Add the Domain in Vercel

1. Open your project in the Vercel dashboard.
2. Go to **Settings → Domains**.
3. Type `jgaos2026-gif.com` and click **Add**.
4. Vercel will display the DNS records you need to add (see next step).
5. Also add `www.jgaos2026-gif.com` and when prompted, choose **"Redirect to jgaos2026-gif.com"**. This ensures all `www` traffic is permanently redirected to the apex domain and the CORS policy remains consistent.

### 4b. Configure DNS at Your Registrar

Log in to the registrar where `jgaos2026-gif.com` is registered (e.g., Namecheap, GoDaddy, Porkbun, Google Domains). Add the following DNS records:

#### Option A — Apex domain with CNAME flattening (recommended for most registrars)

| Type | Name | Value | TTL |
|---|---|---|---|
| `CNAME` | `@` (or blank) | `cname.vercel-dns.com` | 300 |
| `CNAME` | `www` | `cname.vercel-dns.com` | 300 |

> Some registrars (GoDaddy, Namecheap) do not support CNAME on the apex `@` record. Use Option B if yours does not.

#### Option B — A record for apex + CNAME for www

| Type | Name | Value | TTL |
|---|---|---|---|
| `A` | `@` (or blank) | `76.76.21.21` | 300 |
| `CNAME` | `www` | `cname.vercel-dns.com` | 300 |

> Vercel's IP is `76.76.21.21`. This is the correct Anycast IP for the Vercel edge network.

#### Verification

After saving DNS records, return to Vercel **Settings → Domains**. Vercel will automatically verify the records and provision a free TLS certificate (Let's Encrypt). This usually takes 5–30 minutes. Full DNS propagation worldwide can take up to 48 hours.

## 5. Register GitHub Actions Secrets

For the automated deployment workflow (`.github/workflows/vercel-deploy.yml`) to work, add these secrets in **GitHub → Settings → Secrets and variables → Actions**:

| Secret | How to get it |
|---|---|
| `VERCEL_TOKEN` | [vercel.com/account/tokens](https://vercel.com/account/tokens) → Create Token |
| `VERCEL_ORG_ID` | Vercel Dashboard → Team Settings → General → Team ID |
| `VERCEL_PROJECT_ID` | Vercel Project → Settings → General → Project ID (bottom of page) |

Once secrets are added, every push to `main`/`master` automatically deploys to production, and every PR gets a live preview URL.

## 6. Configure Stripe for Production

This app uses Stripe Payment Links (generated by `/api/payments/stripe-link`) to collect deposits and final payments. The `STRIPE_SECRET_KEY` env var must be set in Vercel for payment link creation to work.

> **Webhook handler:** The current codebase does not include a Stripe webhook endpoint. If you add one (e.g., `app/api/webhooks/stripe/route.ts`), register it in the Stripe Dashboard pointing to `https://jgaos2026-gif.com/api/webhooks/stripe`, then update `STRIPE_WEBHOOK_SECRET` in Vercel environment variables accordingly. Be sure to whitelist `/api/webhooks/stripe` as a public path in `middleware.ts` (no auth required for Stripe to reach it).

## 8. Update CORS for Your Domain

The `vercel.json` in this repository sets:

```json
"Access-Control-Allow-Origin": "https://jgaos2026-gif.com"
```

When you add `www.jgaos2026-gif.com` in Vercel's Domains settings (step 4a), select **"Redirect to jgaos2026-gif.com"** so that the `www` subdomain always redirects to the apex. Because of this redirect, browsers will always be on `https://jgaos2026-gif.com` when making API calls, so a single-origin CORS header is correct.

If you add additional client origins (e.g., a mobile app or a staging subdomain), implement dynamic CORS handling inside the relevant API route handlers instead of adding more static `Access-Control-Allow-Origin` headers in `vercel.json`, since static headers can only carry a single value.

## Troubleshooting

### Domain shows "Invalid Configuration" in Vercel

- Wait up to 30 minutes for DNS propagation.
- Use [dnschecker.org](https://dnschecker.org) to verify records are visible globally.
- Confirm no conflicting `A`/`CNAME` records exist at your registrar.

### API routes return 500

- Check Vercel Function Logs: Project → Deployments → [latest] → Functions tab.
- Verify all required environment variables are set in Vercel (not just locally).
- Confirm `NEXT_PUBLIC_SUPABASE_URL` and `SUPABASE_SERVICE_ROLE_KEY` are correct.

### Build fails with TypeScript errors

- Run `npm run type-check` locally and fix any type errors before pushing.
- Vercel mirrors the `npm run build` output — fixing the build locally will fix it on Vercel.

### `Access-Control-Allow-Origin` errors from the browser

- Update the CORS header in `vercel.json` to match the exact origin making the request.
- Ensure `OPTIONS` preflight requests are handled (Next.js handles these automatically for App Router routes).

## Architecture Notes

- **API routes** (`/api/*`) run as Vercel Serverless Functions (Node.js runtime).
- **Middleware** (`middleware.ts`) runs on the Vercel Edge Network — fast, globally distributed.
- **Static assets** are served from the Vercel CDN edge.
- **No Docker or Kubernetes** is required for this deployment path.
